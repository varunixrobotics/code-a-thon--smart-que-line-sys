04Counter Assignment

The next person who is actually here.

Counters only call people who are on site. If you're running late, the counter moves on to the next person instead of waiting.

  • Present first

    Only tokens checked in by location or at the desk can be called.

  • Earliest slot wins

    Checked-in tokens are called in slot order.

  • Least-busy counter

    Auto-assign fills free counters, starting with the one that has served the fewest people.

  • Missed call? You move back.

    Your token moves to a later slot. After two misses it expires.

07Reliability & Scalability

Built for the Monday-morning rush.

Two people can never get the same token, even if they tap at the same moment. The live screen keeps working through network drops.

Atomic token issue

Each seat is claimed inside a single database transaction, and a unique index rejects any second claim on the same seat.

Real-time without polling

Server-Sent Events push changes as they happen, batched per centre and reconnecting on their own.

Scale-out ready

Services are stateless apart from the event hub, which can be swapped for Redis pub/sub to run across many servers.

Rate limited

Separate limits for sign-in, codes, bookings and location updates, by IP address and by user.

Self-healing jobs

A background monitor sends reminders, moves tokens for people who haven't arrived, and clears out old ones.

08Abuse Prevention

Built for people, not bots.

We look at how the cursor moves: its speed, curves, small jitters, and how it approaches a click. Real people move differently from scripts. Try it yourself.

  • Google sign-in or authenticator app (TOTP) required
  • Server-side cursor and typing-rhythm analysis
  • Press-and-hold check timed by the server
  • One token per place per day · max 3 active
  • Repeated no-shows pause booking for 7 days
  • Check-in only works inside the geofence
